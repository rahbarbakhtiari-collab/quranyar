ROOT CAUSE
- Program state-changing POST was handled from QYS_Programs_Module::page().
- Standalone portal template prints document/header before do_shortcode().
- Redirect therefore occurred during render instead of pre-render PRG routing.
- On server/output-buffer combinations where headers were already committed, state changed but redirect could fail, leaving the portal shell with an empty main region.

IMPLEMENTED
- route_portal_post() on template_redirect priority 8.
- route_admin_post() on admin_init priority 60.
- Removed late handle_post() call from page() render path.
- Canonical redirect preserves program_id, applicant filters and #qys-program-applicants anchor.
- headers_sent fallback renders a visible completion state/link instead of blank shell.
- Program notification enqueue now has queue_for_applications_safe().
- Single and bulk applicant status handlers use fail-soft notification enqueue.
- Added Health contract/card: Program action routing.
- Added migration 20261011_042_rc54_program_pre_render_post_redirect owned by programs.
