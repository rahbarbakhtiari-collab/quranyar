IMPLEMENTED IN C6
- Program-domain runtime persistence is now owned by QYS_Program_Repository.
- QYS_Program_Service and QYS_Programs_Module contain no direct $wpdb usage or SQL literals.
- Added repository transaction, admission, audit, Program/Application/Enrollment/Form, attendance-link, member-record and reconciliation operations.
- QYS_Members_Module no longer writes birthday_log directly; member-scoped pending birthday cancellation is owned by QYS_Member_Repository.
- QYS_Targeted delegates runtime metadata insert, launch timestamp, cancel timestamp and due-schedule selection to QYS_Campaign_Repository.
- Targeted schema DDL remains in the owning feature; it is not runtime domain persistence.
- QYS_Multitenant delegates runtime transaction and audit persistence to QYS_University_Repository.
- Cross-domain attendance-open safety read is delegated to the Attendance domain API instead of issuing SQL from Multitenant.
- Multitenant schema DDL/introspection remains with the schema owner.
- Added infrastructure migration 20261006_013_rc24_repository_ownership owned by the Programs lifecycle module.
- No physical schema/domain data migration; schema remains 2026.10.05.7.

PERSISTENCE CONTRACT
- Business/service layers coordinate policy and transactions but do not own SQL for repository-backed tables.
- Shared Program tables => QYS_Program_Repository.
- Member tables / member-scoped birthday cancellation => QYS_Member_Repository.
- Campaign/queue/targeted runtime metadata => QYS_Campaign_Repository.
- Universities/representative runtime persistence + tenant audit => QYS_University_Repository.
- Feature-local DDL/diagnostics may remain in the owning module/installer.
- Legacy self-owned domains without a pre-existing repository are not converted into new repositories in C6; that class-splitting work is a separate P2-04 concern.
