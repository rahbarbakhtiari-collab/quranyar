IMPLEMENTED IN C5
- Broke Programs <-> Attendance into a one-way feature dependency.
- Added core contract QYS_Program_Attendance_Port and QYS_Program_Attendance_Boundary.
- Added Attendance-owned QYS_Attendance_Program_Adapter.
- Programs no longer directly reference QYS_Attendance or QYS_Attendance_Programs.
- Attendance remains allowed to depend on Programs; Module Lifecycle now declares attendance -> programs explicitly.
- Program terminalization, QR creation/read, member attendance summary and legacy attendance backfill cross the narrow boundary.
- Missing Attendance adapter fails closed for attendance creation/linked terminalization while non-attendance Programs remain usable.

- Broke Permission <-> Targeted.
- QYS_Permission_Service no longer references QYS_Targeted.
- Canonical Targeted metadata table/read contract now lives behind QYS_Campaign_Repository methods:
  targeted_meta_table(), targeted_meta_ready(), targeted_meta(), targeted_visible_in_scope().
- QYS_Targeted delegates its table/schema readiness to the repository boundary.
- Targeted continues to depend on Permission, but Permission no longer depends back on Targeted implementation.

- Broke Security <-> Multitenant.
- Canonical owner/page option keys and entry slugs moved to QYS_Config.
- QYS_Security_Service resolves global-owner authority and protected app surfaces directly from QYS_Config + WordPress state.
- QYS_Security_Service has no reference to QYS_Multitenant.
- QYS_Multitenant keeps backward-compatible constants as aliases to QYS_Config.

MODULE LIFECYCLE
- Module count remains 17.
- Attendance dependencies are now: core, universities, programs.
- If Programs fails, Attendance is blocked; Programs no longer becomes dependent on Attendance implementation.
- Attendance adapter is registered during Attendance module boot.
- Lifecycle health checks boundary wiring without adding a new runtime schema-introspection cost.
