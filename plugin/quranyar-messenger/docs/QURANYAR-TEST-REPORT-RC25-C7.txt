IMPLEMENTED IN C7
- Added QYS_Module_Registry as the canonical owner of lifecycle modules and portal feature metadata.
- QYS_Module_Manager no longer stores a second module object registry.
- QYS_Module_Contract now exposes module-owned features().
- Existing 10 portal features are declared by their real lifecycle owner modules.
- Replaced the historical feature-navigation lifecycle module with critical module-registry; total module count remains 17.
- Added QYS_Portal_Feature_Service for tenant permission filtering, module availability and dispatch.
- QYS_Module_Registry is pure metadata and has no dependency on Multitenant, PermissionService or ModuleManager.
- Internal runtime no longer references QYS_Feature_Registry; the class remains only as a backward-compatibility facade.
- Permission vocabulary used for registry validation now lives in QYS_Config::PERMISSIONS; QYS_Multitenant::PERMISSIONS remains a compatibility alias.
- Health Center adds Module registry readiness and per-module Feature count.
- Added infrastructure migration 20261006_014_rc25_module_registry owned by module-registry.
- No physical schema/domain data migration; schema remains 2026.10.05.7.

REGISTRY CONTRACT
- Module identity/dependencies/migrations/health/features are registered through one canonical module registry.
- Feature owner is derived from the registering module; feature metadata cannot claim another module owner.
- Feature IDs and sections are globally unique.
- Permission vocabulary is validated without depending on Multitenant implementation.
- Portal authorization is outside the pure registry boundary.
- Failed/blocked owner modules remain unavailable through QYS_Portal_Feature_Service.
